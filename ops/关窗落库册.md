# 关窗落库册（业务窗关账）

- 生效日：2026-11-21（当天锁定，禁止改口）
- 适用范围：`POST /api/windows/{wid}/close` 及其落库、回执、锁、审计、争用。
- 选定路径：甲（`status` 改为「已关闭」与写入 `seal_token` 同事务提交；提交失败则回执不得成功）

## 唯一正确性口径

甲路径，不得与乙路径混用。乙路径（先写 `close_draft` 再原子切换正式状态）本仓不采用，也不得出现
`close_draft` 表、草稿状态或「先回执后落库」的写法。

### 甲路径硬约束

1. `UPDATE windows SET status='已关闭', seal_token=?` 与关窗审计写入必须在同一事务内提交。
2. 回执只在事务提交成功之后生成；提交失败、校验失败、异常回滚时，回执不得为成功，也不得带出
   `seal_token`。
3. 提交后必须回读 `status` 与 `seal_token` 并与回执逐字段比对；不一致即回滚并按失败返回。
4. 已关闭窗口再次关窗：仅原关账人可幂等重放（`already=true`，令牌取库内既有 `seal_token`，
   不得生成第二枚）；他人后到只记争用并拒发成功回执，即使赢家已释锁。
5. 窗口条带（`GET /api/windows`）、详情（`GET /api/windows/{wid}`）、令牌字段（`seal_token`）、
   审计（`audit_trail` 的 `window_close`）与争用（`contention_log`）五处必须同态：状态、令牌一致。
6. 两人同时关同一窗：先到者占窗锁并在业务提交后释锁；后到者只登记争用（`contention_log` +
   审计 `window_close_contention`），不写业务、不生成令牌。
7. 释锁不得早于业务提交/回滚结论；失败路径不得把未提交业务写一并提交。

## 偏离处置

代码声明路径必须与本册一致。若代码路径偏离本册（或本册缺失、被改写），关窗写路径必须拒绝落库，
并在审计中记录动作「关窗偏了」（`close_ledger_deviation`），不得返回成功回执。
